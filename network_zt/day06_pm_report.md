### 문제 5-1 · 설치를 확인하고 첫 컨테이너 실행하기

- (가) `docker --version` 으로 나온 값을 적어 주세요.

  - 쓸 내용: 「Docker version … build …」 한 줄
  - 답: Docker version 29.7.2, build a7dcaa6
- (나) 🔍 `docker run hello-world` 출력이 말하는 일의 순서를 5.5 그림의 번호(① ~ ④)에 맞춰 설명해 주세요.

  - 쓸 내용: ① ~ ④ 번호마다 한 일 (클라이언트 · 엔진 · Docker Hub · 컨테이너)
  - 답:  도커 클라이언트가 데몬에 연결해 요청한다.
  - 이미지가 없으면 도커허브에서 pull 해옴
  - 컨테이너를 만들어 실행하ㅓ고 컨테이너가 메시지를 출력한다
  - 그 출력을 도커 데몬이 출력을 클라이언트에 보내고 터미널에 출력함

  * **① 클라이언트** : Docker 클라이언트가 Docker 엔진(데몬)에 **연결해 요청**한다. "데몬으로 실행된다"는 틀린 표현이에요.
  * **② Docker Hub** : 엔진에 이미지가 없어서 Docker Hub에서 hello-world 이미지를 pull 한다.
  * **③ 컨테이너** : **엔진이** 그 이미지로 새 컨테이너를 만들어 실행하고, 컨테이너가 메시지를 출력한다.
  * **④ 엔진 → 클라이언트** : 엔진이 출력을  **클라이언트로 보내고** , 클라이언트가 터미널에 보여 준다. 터미널에 직접 보여 주는 건 엔진이 아니라 클라이언트예요.
- (다) 🔍 `docker images` 에 보인 것과 `docker ps -a` 에 보인 것은 각각 이미지와 컨테이너 중 무엇이고, 어떻게 다른가요?

  - 쓸 내용: ① images 에 보인 것과 그 종류 ② ps -a 에 보인 것과 그 종류 ③ 둘의 차이
  - 답: images: 4개, docker ps -a: 3가지, 이미지는 컴퓨터에 존재하는 이미지이고, ps -a 에 보이는 거는 이미지로 실제로 생성된 컨테이너
  -

## 7교시 · 내 페이지 연결 · 두 서버 · 올리기

### 문제 7-1 · 컨테이너 안의 변경이 사라지는 것을 보고, 내 폴더를 연결하기

- (가) 컨테이너 안에서 바꾼 뒤 `docker rm -f web` 으로 지우고 다시 켰을 때 화면이 어떻게 되었는지 적어 주세요.
  - 쓸 내용: ① 바꾼 뒤 화면 ② 지우고 다시 켠 뒤 화면
  - 답: 원래대로 바꾼게 적용돼서 site one 텍스트가 보임, 지우고 다시 켜니 원래대로 welcome nginx 창이 보임
- (나) 🔍 컨테이너 안에서 바꾼 내용이 사라진 이유와, `-v` 로 폴더를 연결하면 무엇이 달라지는지 적어 주세요.
  - 쓸 내용: ① 사라진 이유 ② -v 로 연결하면 달라지는 점
  - 답: 컨테이너를 삭제하고 다시 켰기 때문이다. 변경사항은 컨테이너 안에서만 유지된다. -v로 폴더를 연결하면 컨테이너를 새로 실행해도 연결된 경로에 있는 폴더의 변경사항이 유지된다.
- (다) 🔍 `MSYS_NO_PATHCONV=1` 없이 `-v` 를 실행했을 때 화면에 무엇이 나왔고 왜 그랬는지 적어 주세요.
  - 쓸 내용: ① 화면에 나온 것 ② 그렇게 된 이유
  - 답:  내 컴퓨터 폴더와 연결이 안되고 원래 welcome nginx 창이 나옴, git bash가 자동으로 -v 뒤의 경로를 바꿔버렸기 때문에 연결이 엉뚱한 곳하고 됨
