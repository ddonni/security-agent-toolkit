### 문제 2-2 · 접속 요청 여섯 개를 5대 원칙의 칸으로 분류하기

- (가) 요청 ① ~ ⑥ 은 각각 5대 원칙 중 어느 칸에서 걸리나요? 걸리지 않고 통과하면 「통과」라고 적어 주세요.

  - 쓸 내용: 「①: … / ②: … / ③: … / ④: … / ⑤: … / ⑥: …」 여섯 개
  - 답: id, device, application, network, policy, 통과
- (나) 🔍 요청 ⑤ 는 ID · Device · Application 이 모두 정상인데 왜 Policy 칸에서 걸리나요?

  - 쓸 내용: ① 정상인 것 ② 평소와 달라진 상황 ③ Policy 칸이 하는 일
  - 답: 다른건 다 정상인데 평소와 달리 새벽시간대에 해외ip에서 접속을 했다. policy는 정황적인 정보, 시간, 접속 장소 같은 것들을 확인한다.
- (다) 요청 ③ 과 ④ 는 둘 다 가면 안 되는 곳에 닿으려는 시도인데 왜 서로 다른 칸에서 걸리나요?

  - 쓸 내용: ① ③ 이 확인하는 것 ② ④ 가 확인하는 것
  - 답: ③은 「누가 무엇에 접근하나」를 봐서 권한이 없어 걸렸고, ④는 「어떤 길로 가나」를 봐서 허용되지 않은 경로라 걸렸다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.

  - 쓸 내용: 자유롭게
  - 답: 사내 IP에서 들어왔다고 믿으면 안 된다는 것. 앞 문제의 새벽 접속도 내부 IP라서 방화벽을 통과했어요.

  * 모든 칸이 정상이어도 시간·장소 같은 정황이 평소와 다르면 Policy에서 막을 수 있다는 것.
  * 같은 "가면 안 되는 곳"이라도 권한 문제와 경로 문제는 다른 칸에서 걸린다는 것.

### 문제 3-1 · 권한 변경 판단 함수의 점수 직접 정하기

- (가) 내가 채운 코드 여덟 줄을 붙여 넣어 주세요.
  - 쓸 내용: `# ←` 여덟 곳에 채운 코드(점수 세 개 · 역할 검사 두 줄 · MFA 점수 블록 세 줄)
  - 답:

```
HEALTH_POINTS = 50                                          # 기기 보안 상태 이상일 때 더할 점수. 0 을 알맞은 숫자로 바꾼다 (1줄)   # ←
MFA_POINTS = 30                                               # MFA 안 함일 때 더할 점수. 0 을 알맞은 숫자로 바꾼다 (1줄)   # ←
COUNTRY_POINTS = 30                                           # 해외에서 접속했을 때 더할 점수. 0 을 알맞은 숫자로 바꾼다 (1줄)   # ←

if account["role"] != "account_admin":
        return "거부", ["관리자 역할이 아님"]

if req["mfa"] is False:
        score = score + MFA_POINTS
        reasons.append("MFA 안 함")
```

- (나) 🔍 실행해서 나온 요청 A ~ F 의 결정을 적어 주세요. 모두 기대 결정과 같은지도 함께 적어 주세요.

  - 쓸 내용: 「A: … / B: … / C: … / D: … / E: … / F: …」 여섯 개와 「기대 결정과 같음 · 다름」
  - 답: 허용 거부 추가확인 추가확인 추가확인 거부 기대 결정과 다름(기기 보안은 거부가 나와야 하므로 50으로 수정)
- (다) 🔍 점수 세 개를 정하면서 찾은 조건을 적어 주세요. 점수 하나가 가질 수 있는 범위와, 두 점수의 합이 만족해야 하는 조건이 있나요?

  - 쓸 내용: ① 기기 보안 상태 이상 점수의 범위 ② MFA 점수와 해외 점수의 범위 ③ 둘의 합이 만족해야 하는 조건과 그 이유(요청 몇 번 때문인지)
  - 답:

  ① 기기 보안 상태 이상 점수:  **50 이상** . 이 신호 하나만으로 요청 D가 거부돼야 하므로 거부 기준인 50점에 혼자 도달해야 합니다.

  ② MFA 점수와 해외 점수: 각각  **10 이상 49 이하** . 요청 C와 E는 신호가 하나씩만 있는데 결과가 추가확인이어야 하므로, 10점 이상이되 50점 미만이어야 합니다.

  ③ 두 점수의 합:  **MFA 점수 + 해외 점수 ≥ 50** . 요청 F는 두 신호가 함께 있을 때 거부돼야 하기 때문입니다. 예를 들어 20 + 20처럼 각각은 범위 안이어도 합이 40이면 F가 추가확인이 되어 틀립니다.
- (라) 🔍 기기 보안 상태 이상은 정산 조회에서는 추가확인인데 권한 변경에서는 거부입니다. 왜 기준이 다른가요?

  - 쓸 내용: ① 정산 조회에서 그 신호의 점수와 결정 ② 내가 정한 권한 변경 점수와 결정 ③ 기준이 다른 이유
  - 답: 권한 변경은 관리자가 할 수 있는 작업이라 보안과 직결되있는 사항이다. 공격자 계정에 권한을 준다던지 악의적으로 사용되면 큰 피해를 초래할 수 있기 때문에 더 엄격한 기준을 적용해야한다.

  ① 정산 조회에서 그 신호의 점수와 결정: (이전 과제에서 정한 점수를 적어 주세요) 점 → 추가확인

  ② 권한 변경에서 정한 점수와 결정: 50점 → 거부

  ③ 이유: 같은 신호라도 **요청이 실패했을 때의 피해 크기**가 다르기 때문입니다. 정산 조회는 데이터를 읽기만 하는 요청이라, 추가 인증만 거치면 위험을 충분히 줄일 수 있습니다. 반면 권한 변경은 다른 계정의 권한을 바꾸는 관리자 작업입니다. 보안 상태가 이상한 기기(악성코드 감염 가능성)에서 이를 허용하면 공격자가 관리자 권한을 얻거나 다른 계정을 장악할 수 있어서, 피해 범위가 넓고 되돌리기도 어렵습니다. 그래서 위험한 작업일수록 같은 신호에도 더 엄격한 기준을 적용합니다.
