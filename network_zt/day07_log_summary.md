
# 정산 포털 정책 로그 점검 결과

## 결론

- 검토한 네 가지 안 중에 **정상 요청을 막지 않으면서 위험 요청도 모두 막는 안은 없습니다.**

| 안   | 대량 조회 기준 | 대량 조회 점수 | 정상인데 걸린 건 (오탐) | 위험한데 못 막은 건 (미탐) |
| ---- | -------------- | -------------- | ----------------------- | -------------------------- |
| 현재 | 20건 이상      | 30점           | **6건**           | 0건                        |
| A    | 50건 이상      | 30점           | 0건                     | **1건**              |
| B    | 20건 이상      | 10점           | 0건                     | **2건**              |
| C    | 20건 이상      | 0점            | 0건                     | **2건**              |

* **현재 정책**은 위험 요청을 다 막지만, junho의 평소 마감 업무 6건까지 매번 추가 확인을 요구합니다.
* **A안**이 가장 낫지만 비교용 위험 요청(11번, 해외에서 49건 조회)을 막지 못하고 추가 확인으로만 넘깁니다.
* **B안과 C안**은 위험 요청 두 건을 모두 놓치므로 채택하면 안 됩니다.

### 근거

**용어 풀이**

* **오탐** : 정상 요청을 위험하다고 잘못 판단해서 "허용"이 아닌 결정(추가 확인이나 거부)을 내린 경우입니다. 실제 사용자는 불편을 겪습니다.
* **미탐** : 위험 요청을 놓쳐서 "거부"하지 못한 경우입니다. 보안상 더 심각한 실수입니다.
* **대량 조회 기준(임계값)** : 한 번에 몇 건 이상을 조회하면 "많이 조회했다"고 볼지 정하는 경계 숫자입니다.
* **MFA(다단계 인증)** : 비밀번호 외에 휴대폰 인증 같은 확인을 한 번 더 거치는 로그인 방식입니다. 이번 요청 11건은 모두 등록된 기기에서 MFA를 거쳤습니다.

**점수 규칙**

* 해외에서 접속하면 30점, 조회 건수가 기준 이상이면 안별 점수를 더합니다.
* 합계가 50점 이상이면 거부, 20점 이상이면 추가 확인, 그 아래면 허용합니다.

**안별로 갈린 이유**

* **현재 정책** : 기준이 20건이라 junho의 마감 업무(35~44건) 6건이 모두 30점을 받아 추가 확인으로 분류됩니다. 위험 요청 두 건은 해외 30점 + 대량 30점 = 60점으로 거부됩니다.
* **A안** : 기준을 50건으로 올려 마감 업무는 전부 허용됩니다. 그러나 11번(49건)은 기준에 1건 모자라서 해외 점수 30점만 받아 추가 확인에 그칩니다.
* **B안** : 대량 조회 점수가 10점으로 줄어, 위험 요청 두 건이 40점에 머물러 거부 기준(50점)에 닿지 못합니다.
* **C안** : 대량 조회 점수가 없어 위험 요청이 해외 점수 30점만 받습니다.

**데이터에서 보이는 패턴**

* junho의 정상 요청은 모두 국내이고 최대 44건입니다.
* 위험 요청은 모두 해외이고 49건 이상입니다.
* 정상과 위험 사이에 **45~48건 구간**이 비어 있습니다.

### 권고

1. **B안과 C안은 채택하지 않습니다.** 위험 요청을 하나도 거부하지 못합니다.
2. **대량 조회 기준을 45건으로 정한 새 안(D안, 점수 30점 유지)을 검토합니다.** 같은 데이터로 계산하면 오탐 0건, 미탐 0건입니다. 마감 업무(최대 44건)는 허용되고, 위험 요청(49건, 52건)은 60점으로 거부됩니다.
3. **D안을 바로 확정하지는 않습니다.** 이번 점검은 한 사람의 한 주 기록이고 위험 요청 표본이 2건뿐입니다. 이런 적은 데이터에 숫자를 딱 맞추면 다른 사용자나 다른 주에는 맞지 않을 수 있습니다(과적합). 다른 사용자와 다른 기간의 기록으로 다시 검증해야 합니다.
4. **시간 조건 추가를 검토합니다.** 8번 위험 요청은 목요일 밤 22:40에 들어왔고, 정상 요청은 모두 업무 시간(09~16시)이었습니다. 업무 시간 밖 접속에 점수를 주면 조회 건수 기준에만 기대지 않아도 됩니다.
5. **코드 점검 결과** : 주석으로 표시한 1~6번 단계는 모두 설명대로 구현되어 있습니다. 실제로 실행해서 위 표의 숫자를 확인했습니다.
